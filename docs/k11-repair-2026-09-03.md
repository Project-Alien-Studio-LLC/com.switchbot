# K11+ repair — September 3, 2026

## Deployed scope

- Initialize only unset Homey cleaning selections to Sweep / Quiet / 1 Cycle. These are next-start selections, not telemetry from the vacuum. Initialization never calls robot command listeners.
- Label the K11+ legacy `sweep_mop` option as Mop and translate it to SwitchBot's documented `mop` action. Preserve the capability and enum IDs for existing Flows. The driver manifest override is necessary for the visible label; the runtime-only override did not update the rendered picker on this Homey.
- Propagate fan, water, repeat-count, and volume command rejections back to Homey.
- Opt the K11+ into explicit command-acceptance checking. Missing authentication, missing response codes, and rejected responses fail. An unacknowledged command is not retried; a successful status read cannot turn rejection into success. Other hub drivers retain their previous behavior.
- Accept integer battery readings from 0 through 100 in polling and webhook paths.
- Register the previously missing Dock button handler.
- Support both the three-argument Start-button call and four-argument shared Flow call, so Flow water level does not replace cycle count.
- Retain the pre-existing K11+ mode-dependent water-control logic. No water capability existed on the live Sweep-mode device before or after this deployment.

## Deployment notes

The isolated candidate is `/tmp/switchbot-k11-repair.jRT9R6/candidate`; the reconstructed prior baseline is its sibling `baseline`. The parent directory is private. Original credentials, pairings, device stores, and Flows were preserved; no clean install was used. Temporary paths are not durable backups.

Run the Homey installer **from the app directory**, without using `--path` from another working directory. The installed CLI's production-dependency discovery turns the trailing blank `npm ls` output line into a path relative to the caller's working directory. An initial packaging attempt from the SmartHome directory began making unintended local copies; it was interrupted before upload and the generated copies were moved into a private quarantine inside the temporary staging directory. Original files and the running Homey app were unaffected by that attempt.

The final candidate installed successfully, with the existing runtime environment supplied. The manifest contains only a K11+ capability-option change; shared-driver changes are guarded by the K11+-only opt-in.
